# Story を使ったコンポーネントテストの比較

React コンポーネントのテストを、どの方式で書くかを決めるための材料です。

## 前提: どれか 1 つを選ぶ

複数の方式を組み合わせて 1 つのスイートを作るためのリポジトリではありません。
**競合する方式のうちどれを採用するかを決める**ためのもので、
採用が決まれば、選ばれなかった実装はまるごと消えます。

そのため、競合する方式はそれぞれが**単独で全ケースを賄えるように**実装してあります。
ケースを方式どうしで分担すると、単独で採用できるかどうかが判断できないためです。

収録物には、競合するものとしないものが混ざっています。

|                                                   | 関係                                                    |
| ------------------------------------------------- | ------------------------------------------------------- |
| **方式A** Story に書く（play 関数）               | **競合する**。テストの正をどこに置くかの選択            |
| **方式B** テストファイルに書く（Testing Library） | **競合する**。方式Aとどちらか一方だけが残る             |
| 実ブラウザ実行 / Portable Stories（jsdom）        | 方式Aを選んだ場合の**下位の選択**。実行環境をどうするか |
| スモークテスト / a11y                             | **競合しない**。ただし得られる件数は方式に連動する      |
| 描画を伴わない検証（純粋関数）                    | **競合しない**。方式の選択と独立                        |

## 読む順番

前半（1〜3）が判断材料、後半（4〜7）が採用後の書き方、8 は付録です。

| 章                            | 中身                                        |
| ----------------------------- | ------------------------------------------- |
| 1. 何を検証するか             | ケースを技法から導出する                    |
| 2. 選択肢と比較               | 記述量・実行時間・カバレッジ・検出力        |
| 3. 環境差と落とし穴           | 実ブラウザと jsdom で実際に違った点         |
| 4. 方式A Story に書く         | play 関数の書き方                           |
| 5. 方式A jsdom で回す         | Portable Stories（方式Aの実行環境の選択肢） |
| 6. 方式B テストファイルに書く | Testing Library の書き方                    |
| 7. どちらでも足せるもの       | スモークテストと a11y                       |
| 8. このリポジトリの構成       | ディレクトリとツールチェイン（実装者向け）  |

## 比較の土台になるケース

「書き方が違う」以上のことを言うために、`LoginForm` に対する検証ケースを固定しています。

ケースは思いつきではなく技法から導出しています。
状態遷移テストで T1〜T6、デシジョンテーブルで D1〜D4、
同値分割・境界値分析で V1〜V8、操作経路で K1。導出の過程は「1. 何を検証するか」にあります。

ケースを洗い出す過程で、実装の欠陥が 2 件見つかりました。
送信失敗時に未処理の Promise 拒否になっていたことと、
Enter キーによる二重送信を防いでいなかったことです。

## 対象から外したもの

2026 年 8 月時点で、本番で採用しうるものだけに絞っています。
Storybook 8 で削除された storyshots、更新の止まっている vitest-axe、
Vite 構成では出番のない test-runner は入れていません。

## このドキュメントの書き方

解説には、このリポジトリで実際に観測できたことと、それを再現する方法だけを書いています。

- 実行時間・カバレッジ・エラーメッセージ・バージョンは、すべて手元で計測した値です
- 「こう書くべき」「こうしたほうがよい」といった一般論は書きません
- 方式の優劣は断定せず、観測された差だけを並べます。選ぶのは読み手です

## テストの実行

```bash
npm run test           # 全部
npm run test:stories   # 実ブラウザ
npm run test:unit      # jsdom
npm run test:portable  # 方式A の jsdom 実行だけ
npm run test:plain     # 方式B だけ
```

Vitest の project を実行環境で分けているので、片方だけを回せます。

手法単位の実行は、収集条件ではなく実行時のファイル名で絞っています。
`include` を手法別サフィックスで絞ると、規約から外れた名前のテストが
警告もなく無視されるためです（「3. 環境差と落とし穴」を参照）。
