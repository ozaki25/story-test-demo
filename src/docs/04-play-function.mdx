# 方式A Story に書く

Story に `play` 関数を書くと、その Story が「表示の確認」から「振る舞いの検証」に格上げされます。
Storybook の UI 上ではインタラクションが再生され、
`npm run test:stories` では Vitest のテストとして実行されます。

対象ファイル: `src/components/LoginForm/LoginForm.stories.tsx`

## 書き方

```tsx
export const EmptySubmitShowsErrors: Story = {
  name: "S1 空のまま送信するとエラーが出る",
  play: async ({ canvas, userEvent, args, step }) => {
    await step("空のままログインボタンを押す", async () => {
      await userEvent.click(canvas.getByRole("button", { name: "ログイン" }));
    });

    await step("両方の項目にエラーが表示される", async () => {
      await expect(await canvas.findByText("メールアドレスを入力してください")).toBeInTheDocument();
    });
  },
};
```

`canvas` は Story の描画範囲に束縛された Testing Library のクエリ、
`userEvent` は Storybook が用意した操作 API です。どちらも play の引数から受け取れます。
`args` には Story の args がそのまま入るので、`fn()` で作ったスパイの呼び出しも検証できます。

`step` は必須ではありません。付けると、失敗時にどの段階で落ちたかが
Storybook の Interactions パネルに表示されます。

## 向いているもの

- ユーザーの操作を伴う振る舞い（入力、送信、開閉、フォーカス移動）
- 「この状態の見た目」もカタログとして残したいもの
- 実ブラウザでしか再現しない挙動（フォームの標準バリデーション、レイアウト依存の操作）

## 向いていないもの

- 描画を伴わない純粋なロジック。関数として切り出せば、描画なしで検証できる
- 大量の入力パターンの網羅。パターンの数だけ Story が増え、カタログに並ぶ

## 注意点

`args` にスパイを置くと、Storybook の UI では Actions パネルに呼び出しが表示され、
テストとして実行されるときは呼び出し引数の検証に使えます。1 つの定義が両方で機能します。

```tsx
const meta = {
  args: { onSubmit: fn() },
} satisfies Meta<typeof LoginForm>;
```

## 人間向けの Story と検証用の Story を分ける

play 関数を書き始めると Story が増えます。放っておくと、
サイドバーが「T6 送信中に submit が再度発火しても二重送信されない」のような
**検証の手順**で埋まり、カタログとして機能しなくなります。

Story には 2 つの役割があるので、分けて扱います。

| 役割     | 目的                 | 例                                           |
| -------- | -------------------- | -------------------------------------------- |
| 人間向け | その状態を見る       | 初期表示、入力エラー表示、送信中、送信失敗   |
| 検証用   | 遷移や経路を確かめる | T2 復帰、T4 成功、T6 二重送信、K1 キーボード |

検証用にはタグを付けてサイドバーと Docs から外します。

```tsx
export const NoDoubleSubmit: Story = {
  tags: ["!dev", "!autodocs"],
  name: "T6 送信中に submit が再度発火しても二重送信されない",
  play: async ({ canvas, userEvent, args, step }) => {
    /* ... */
  },
};
```

`test` タグは既定で付いたままなので、**隠しても実行されます**。
このリポジトリでは、隠したあとも実ブラウザ側のテストは 19 件のままで、
axe も全 Story に対して回っています。カタログを汚さずに検証だけを増やせます。

`Button` にはこのタグを付けていません。variant や size の Story はすべて
「その状態を見る」ためのもので、検証用の Story がないためです。
コンポーネントの性格によって、分ける必要があるかどうかは変わります。
