# 方式A Story に書く

Story に `play` 関数を書くと、表示を確認するだけだった Story が振る舞いの検証も兼ねるようになります。
Storybook の UI 上ではインタラクションが再生され、
`npm run test:stories` では Vitest のテストとして実行されます。

対象ファイル: `src/components/LoginForm/LoginForm.stories.tsx`

## 書き方

```tsx
export const EmptySubmitShowsErrors: Story = {
  name: "S1 空のまま送信するとエラーが出る",
  play: async ({ canvas, userEvent, args, step }) => {
    await step("空のままログインボタンを押す", async () => {
      await userEvent.click(canvas.getByRole("button", { name: "ログイン" }));
    });

    await step("両方の項目にエラーが表示される", async () => {
      await expect(await canvas.findByText("メールアドレスを入力してください")).toBeInTheDocument();
    });
  },
};
```

`canvas` は Story の描画範囲に束縛された Testing Library のクエリ、
`userEvent` は Storybook が用意した操作 API です。どちらも play の引数から受け取れます。
`args` には Story の args がそのまま入るので、`fn()` で作ったスパイの呼び出しも検証できます。

`step` は必須ではありません。付けると、失敗時にどの段階で落ちたかが
Storybook の Interactions パネルに表示されます。

## 向いているもの

- ユーザーの操作を伴う振る舞い（入力、送信、開閉、フォーカス移動）
- 操作した結果の状態を axe の検査対象に含めたいもの
- 実ブラウザでしか再現しない挙動（フォームの標準バリデーション、レイアウト依存の操作）

## 向いていないもの

- 描画を伴わない純粋なロジック。関数として切り出せば、描画なしで検証できる
- 大量の入力パターンの網羅。パターンの数だけ Story が増え、カタログに並ぶ

## 注意点

`args` にスパイを置くと、Storybook の UI では Actions パネルに呼び出しが表示され、
テストとして実行されるときは呼び出し引数の検証に使えます。1 つの定義が両方で機能します。

```tsx
const meta = {
  args: { onSubmit: fn() },
} satisfies Meta<typeof LoginForm>;
```

## play がある Story はテスト用として扱う

play 関数を書き始めると Story が増えます。放っておくと、
サイドバーが「T6 送信中に submit が再度発火しても二重送信されない」のような
**検証の手順**で埋まり、カタログとして機能しなくなります。

このリポジトリでは、振り分けを 1 つの規則で決めています。

> play 関数があるものはテスト用。人間向けは args だけで作る。

例外を作らないので、Story ごとに「これは人にも見せるか」を判断する必要がありません。
その判断は状態が増えるたびに発生し、人によって答えも変わります。

規則は Docs ページの制約とも一致します。Docs では play が走らないため、
play で状態を作る Story を人間向けに置くと、名前だけ違う空の状態が並びます
（「3. 環境差と落とし穴」を参照）。args だけで作る Story にはこの問題が起きません。

`LoginForm` では `Default` だけが人間向けで、残り 10 件がテスト用です。
11 ケースのうち T1 と D4、T3 と D1 はそれぞれ 1 つの Story で賄っています。
テスト用には独自タグを付けます。ここでは `interaction` という名前にしています。

```tsx
export const NoDoubleSubmit: Story = {
  tags: ["interaction", "!autodocs"],
  name: "T6 送信中に submit が再度発火しても二重送信されない",
  play: async ({ canvas, userEvent, args, step }) => {
    /* ... */
  },
};
```

そのタグを `.storybook/main.ts` で既定除外にすると、サイドバーから畳まれます。

```ts
tags: {
  interaction: { defaultFilterSelection: "exclude" },
},
```

`test` タグは既定で付いたままなので、**畳んでも実行されます**。
このリポジトリでは、畳んだあとも実ブラウザ側のテストは 19 件のままで、
axe も全 Story に対して回っています。

### 畳むか、完全に隠すか

`tags: ["!dev"]` を付けると、サイドバーからもタグフィルタからも消えます。
独自タグで既定除外なら、検索欄の横のフィルタに
`interaction (excluded) 10` と件数が出ます。

|                        | `!dev`       | 独自タグで既定除外    |
| ---------------------- | ------------ | --------------------- |
| 既定のサイドバー       | 1 件         | 1 件                  |
| 隠れているものへの導線 | ない         | フィルタに件数が出る  |
| 表示に戻す操作         | ソースを触る | フィルタを 1 クリック |
| 検索でヒットする       | しない       | 畳んでいる間はしない  |
| URL 直打ちで開ける     | 開ける       | 開ける                |
| 実ブラウザのテスト件数 | 19           | 19                    |

このリポジトリでは後者を採っています。
カタログを汚さずに、テスト用の Story があること自体は UI から辿れます。

`Button` にはこのタグを付けていません。variant や size の Story には play 関数がなく、
規則に照らすとすべて人間向けだからです。同じ規則で判定した結果が、
コンポーネントによって違う形になります。

### 畳んだものを表示に戻す

検索欄の横のフィルタボタンを押すと、次のパネルが出ます。

| 行                             | 既定         | 押すと                                          |
| ------------------------------ | ------------ | ----------------------------------------------- |
| `Clear filters`                | -            | **すべての絞り込みが外れて全 Story が出る**     |
| `Documentation` 11             | チェック済み | Docs 系だけに絞る                               |
| `Play` 10                      | チェック済み | play 関数のある Story だけに絞る                |
| `New` / `Modified` / `Related` | 0            | 変更検知による絞り込み。このリポジトリでは 0 件 |
| `interaction (excluded)` 10    | 除外中       | 除外を解除して表示に加える                      |

`Clear filters` を押すと `LoginForm` は 12 件（Docs・Default・テスト用 10 件）になります。
`interaction` の行を `Include` にしても同じ結果です。

状態は URL に載るので、共有もブックマークもできます。`?tags=` が全表示です。

```
https://ozaki25.github.io/story-test-demo/?tags=
```

チェックボックスは 2 状態のトグルで、押すとそのカテゴリだけに絞り、もう一度押すと戻ります。
右端の `Exclude` / `Include` は**押したときに起きること**で、現在の状態ではありません。
チェックが付いた行に `Exclude` と表示されるので、状態表示と読み違えやすいところです。
